# 06 扫榜雷达与爆款监控（Trend Radar）

## 一、数据来源（只用合规渠道）

| 来源 | 方式 | 说明 |
| :--- | :--- | :--- |
| 番茄公开榜单页 | 用 `/browser` 浏览公开可见的榜单页面，记录排名、书名、标签等可见信息 | 只记录页面上公开展示的内容 |
| 作者后台 | 用户自行导出或截图提供 | 自己作品的读完率、追读、加书架等 |
| 用户手动整理 | 用户粘贴榜单文本 | 由总控整理成 CSV |
| 公开行业报告/新闻 | `search_web` | 用作题材趋势佐证，注明来源与日期 |

**不做**：字体反混淆、APP 接口签名模拟、批量下载正文等绕过平台防护的采集。

## 二、快照 CSV 规范

文件名：`00-radar/YYYY-MM-DD_<榜单名>.csv`，UTF-8 编码。生成模板：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/rank_diff.ps1 -Mode template -Out "00-radar/2026-11-10_男频新书榜.csv"
```

| 字段 | 必填 | 说明 |
| :--- | :- | :--- |
| date | 是 | 采集日期 YYYY-MM-DD |
| list | 是 | 榜单名，例如 男频新书榜 / 女频巅峰榜 |
| rank | 是 | 排名，整数 |
| title | 是 | 书名 |
| author | 否 | 作者 |
| tags | 否 | 标签，用 `/` 分隔，例如 `重生/复仇/豪门` |
| reads | 否 | 阅读/在读数，支持 `12.3万` 写法 |
| words | 否 | 字数，支持 `56万` 写法 |
| status | 否 | 连载/完结 |

## 三、监控流程

1. **采集**：同一榜单、固定周期（建议每周 1-2 次）各存一份快照。
2. **对比**：`rank_diff.ps1 -Mode diff -Old <旧> -New <新>` → 新上榜、跌出榜、排名跃升、阅读增长。
3. **标签热度**：`rank_diff.ps1 -Mode tags -New <快照>` → 按排名加权的标签热度与 Top10 占比。
4. **判断**：
   - **红海**：Top10 占比高（经验值 > 40%）的标签，竞争激烈，要靠新组合突围。
   - **黑马信号**：新上榜且排名跃升快的书 → 进入 P3 拆解候选。
   - **蓝海**：热度在上升，但 Top10 占比还低的标签组合。
5. **报告**：按 [趋势报告模板](../templates/trend-report.md) 输出。

**周期提醒**：可建议用户用 `/schedule` 设置每周提醒，到点后由总控执行 `/monitor`。

## 四、作者后台数据复盘（P8）

| 指标 | 关注点 | 常见原因 → 处理 |
| :--- | :--- | :--- |
| 第 1 章读完率低 | 开头 300 字 | 开场慢 → 按黄金三章重写开头 |
| 第 3-5 章掉点 | 首个爽点闭环 | 爽点来得太晚 → 前移 |
| 某章突降 | 该章内容 | 毒点（圣母、憋屈、注水） → 对照毒点清单 |
| 追读低但读完率高 | 章尾钩 | 钩子弱 → 换钩型 |
| 评论集中吐槽 | 评论关键词 | 分类整理，进入下一轮章纲修订 |
