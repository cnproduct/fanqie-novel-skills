# 小说家（Novelist）

端到端的长篇中文小说生产线。把"想写一本小说"拆成可执行的五个阶段，**每阶段都产出可交付、可追溯的文件**，而非一次性吐出一大段文字。本技能的重点不是"会写"，而是"写得稳、可评估、可上架"。

## 何时使用

- 用户要写长篇/网文（古言、现言、悬疑、玄幻等任意题材），需要分章、控字数、排钩子。
- 用户已有一部小说，要求**质量评估 / 六维打分 / 去AI味 / 人物补强**。
- 用户要**上架发布**（书旗、番茄、起点等）：需要剥离写作元数据、写平台简介、出上架信息单、生成封面。

> 与 `tomato-novelist` 的关系：tomato-novelist 专注番茄平台的分章生成；本技能是 **全生命周期 superset**，在生成之外补上评估、去味、人物、上架四块。两者可配合使用——以 tomato-novelist 起稿，以本技能收尾交付。

## 五大阶段总览

| 阶段 | 产出 | 关键纪律 |
|------|------|---------|
| ① 规划 | `00-大纲.md` / `02-情绪曲线.md` | 五幕结构、钩子轮换表、字数区间 |
| ② 生成 | `第XX章-标题.md` × N | 2200-2800字/章、钩子标注、伏笔标记 |
| ③ 评估 | `质量评估报告.md` / `小说评分报告.md` | 字数纪律、钩子合规、六维评分 |
| ④ 精修 | 直接改章 | 人物补强、去AI味（适配小说） |
| ⑤ 上架 | `发布版/` / `上架信息单.md` / 封面 | 剥离元数据、平台简介、封面 |

## 阶段① 规划（必做，且先于一切生成）

见 [references/planning.md](references/planning.md)，内含：

- **项目目录树**：`novels/[书名]/` 下如何摆放大纲、情绪曲线、章节、报告、发布版。
- **五幕结构模板**：把全书切成 5 个卷（如 弃子/入朝/掌权/对峙/天下），给出每卷的功能与字数分配。
- **钩子轮换系统**：A信息差 / B危机逼近 / C关系转折 / D身份揭秘 / 收束留白 五型，每 5 章为一单元，单元内类型**不得相邻同型**。
- **章节文件格式**：每章含 `## 本章概要`（悬念钩子+伏笔）、`## 正文`、`### 章节备注`（钩子标记+伏笔标记）——这些元数据**绝不进读者稿**（见阶段⑤剥离）。
- **大纲 / 情绪曲线模板**：见 `templates/`。

规划完成后，向用户展示结构摘要并**等确认**再进入生成。

## 阶段② 生成（逐章，含纪律自检）

逐章执行，每章落盘后用脚本自检字数：

```bash
python scripts/wordcount_check.py novels/[书名]/
```

- 每章必须落在 **2200–2800 字**（CJK 计）。低于 2200 扩充，高于 2800 精简。
- 每章必须在 `## 本章概要` 标注悬念钩子类型（A/B/C/D/收），在 `### 章节备注` 写钩子标记与伏笔标记，供阶段③核对。
- 每完成 5 章，生成本阶段**节奏报告**（情绪曲线、爆点密度、钩子分布），并询问用户是否调整后续大纲。

> 生成质量本身（开篇黄金三行、悬念承上启下、展示而非讲述）参考 tomato-novelist 的章节指南；本技能不重复造轮子，聚焦"纪律 + 交付物"。

## 阶段③ 评估（量化，不靠印象）

见 [references/evaluation.md](references/evaluation.md)，给出两套可交付的评估：

1. **质量评估报告（综合版）**：用脚本跑硬指标——字数分布、钩子分布、5章单元轮换合规率、分卷均字均衡度；再附文笔/结构/伏笔回收/爽点/无CP纪律的定性评述。
2. **六维量化评分（对标 novel-evaluator）**：情节架构(25)/人物塑造(20)/文笔质量(15)/世界观(15)/情感共鸣(15)/创新性(10)，附去AI味扫描证据。

关键脚本：

```bash
# 全本字数纪律 + 分卷均衡
python scripts/wordcount_check.py novels/[书名]/

# 钩子轮换合规 + 类型分布（依赖章节里的钩子标注）
python scripts/hook_rotation_check.py novels/[书名]/
```

跑完把数字写进报告，再给"可优化点"清单（按严重程度排序，标注是否为校样级）。

## 阶段④ 精修（两类典型动作）

### 4.1 人物补强
针对"功能性偏强/工具人"角色：在既有道具/线索锚点处补**带体温的个人底色**（怕、梦、旧部之愧、释然），并让该弧光在 2–3 章递进呼应。**严守无CP纪律**：不得引入任何感情线。模板与落点选择见 [references/planning.md](references/planning.md) 的"人物补强"小节。

### 4.2 去AI味（适配小说，不可照搬通用 humanizer）
**关键纪律**：通用 humanizer 的 L1-2 标点禁令（删引号、破折号）对小说是灾难——古言靠引号撑对话、破折号撑停顿，**本技能明令豁免**。正确做法见 [references/deai.md](references/deai.md)：用 humanizer 自己的禁用词/结构清单做**只读扫描**，把命中分成"真杂草"与"小说合法修辞误判"，只做**精准小批**——典型目标是全本重复的 crutch 词（如"心头一震"统一当惊觉反应），换成不同身体动作既去味又破重复。绝不逐章通扫式改写（那会破坏已有文风与字数控）。

## 阶段⑤ 上架发布（交付读者稿）

见 [references/publishing.md](references/publishing.md)，产出四件套：

1. **干净发布版**：`scripts/strip_metadata.py` 剥离全部写作元数据，只留 `## 正文` 到 `---` 之间的正文，按 `001-标题.txt` 顺序导出。
   ```bash
   python scripts/strip_metadata.py novels/[书名]/ novels/[书名]/发布版/
   ```
2. **平台简介**：派 copywriter 改写钩子向版本（首行抛爆点、留钩子、点无CP），并核验字数。
3. **上架信息单**：书名（主推+备选）、女频分类归属、四维度标签、笔名取向——派 copywriter 产出。
4. **封面**：派 image-creator 生成竖版（2:3）暗金权谋风，纯净画面版 + 带字版备选。

> 协作纪律：简介/信息单/封面属专业产出，须走团队流程派给对应成员（copywriter / image-creator），主理人只做编排与汇编，不得代写。

---

## 协作与交付铁律

- 所有跨成员任务走"建组 → 派发 → 回传 → 汇编"，子任务 `name`/`subagent_type` 传成员 Agent ID。
- 每阶段结束向用户通报进度；最终交付清单必须覆盖本阶段全部产物文件。
- 章节内部元数据（钩子标注、伏笔标记、章节备注）是**工程笔记**，发布版必须剥离。
